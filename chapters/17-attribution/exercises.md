# Chapter 17 exercises: Attribution

- Note: each exercise is small, runnable in the chapter's notebook or a fresh Python REPL, and probes one specific point the chapter raised. Two-lens exercises ask both questions explicitly.
- Exercise 1: predict the ranking before running
  - Setup: read Loop A in chapter.log. The true coefficients are direct 0.20, search 0.10, email 0.05, social 0.04, display 0.02.
  - Task: before running any code, write down which heuristic you expect to most overweight `direct`, which to most overweight `search`, and which to most blur all five channels toward equal shares. Then run `simulate_journeys(20000, seed=170)` and call `expkit.attribution.touch.aggregate_credit` with each of the four schemes to verify.
  - Expected pattern: last-touch overweights direct, first-touch overweights search and social (the discovery channels that often start journeys), linear blurs everything toward equal, time-decay sits between linear and last-touch. This matches the figure `images/scheme_comparison.png`.
  - Two-lens: not relevant yet. As Loop B's two-lens commentary says, frequentist attribution is deterministic accounting and there is no statistical test of "which heuristic is right".
  - Stretch: change the journey-length distribution from `rng.integers(1, 6)` to a constant of 1 touch per journey. Predict how the four heuristics collapse and verify.
- Exercise 2: uniform lift, find the misallocation
  - Setup: read Loop B and re-run `render_treatment_lift_misallocation` from `chapters/17-attribution/generate.py`. The treatment uniformly bumps conversion probability for every channel.
  - Task: compute the per-channel relative credit lift for each of the four heuristics. Compare to the truth, which is "every channel should look like it gained the same share".
  - Expected pattern: first-touch concentrates the lift on the channels that tend to start journeys, last-touch concentrates it on `direct`, linear and time-decay are closer to flat but still distort. This is the structural reason "every quarter the attribution report tells a different story" in real teams.
  - Two-lens: still no frequentist inference on this. Loop B is a deterministic allocation problem. Compare to Loop C, where a likelihood model finally gives us something to do statistical inference on.
  - Stretch: design a treatment that *only* lifts journeys ending on `email`. Predict and verify which heuristic gets closest to the truth.
- Exercise 3: skeptical, break the recovery model
  - Setup: read Loop C. The Bayesian model in `chapters/17-attribution/generate.py` `render_bayesian_attribution` recovers the true coefficients because data was generated from a logistic-additive model and the same form was fit.
  - Task: change the data-generating process to encode an *interaction*: when a user touches both `email` and `direct` the conversion score gets an extra +0.10 on top of the additive sum. Refit the same additive PyMC model. Inspect the posterior.
  - Expected pattern: the additive model now mis-recovers individual channel coefficients. The interaction mass leaks into the marginal coefficients on `email` and `direct`. The 95% credible intervals may still bracket zero or the truth, but the model is wrong about the mechanism. This is exactly the "specification" caveat at the end of Loop D.
  - Two-lens: the model is already Bayesian. The frequentist counterpart is to fit the same logistic regression with `statsmodels.GLM(family=Binomial())` and inspect the maximum-likelihood point estimates and Wald CIs. Verify that the same misspecification damages both lenses identically: the issue is the design matrix, not the inference machinery.
  - Stretch: add an `email_x_direct` interaction column to the design matrix and refit. Does the model now recover both the marginals and the interaction?
- Exercise 4: order-blindness probe
  - Setup: Loop D ends with a caveat on order-blindness: touch-count covariates collapse the journey to a bag of channels.
  - Task: take the simulated journeys from `simulate_journeys(20000, seed=170)`. For each journey, *reverse* the touch order before passing through `aggregate_credit`. Recompute first-touch, last-touch, linear, and time-decay credit shares.
  - Expected pattern: linear is invariant. Time-decay is invariant up to the choice of "last" timestamp. First-touch and last-touch swap roles entirely. The Bayesian additive model from Loop C is also invariant, because its design matrix only counts how many times each channel was touched, not when. This is the chapter's caveat made operational.
  - Two-lens: which heuristic is "right" depends on whether sequence carries information. Both lenses give the same answer when sequence does not matter. They give different answers when it does, and the Bayesian additive model is silent about that difference unless you add `first_is_X` and `last_is_X` columns to the design matrix as Loop D suggests.
  - Stretch: add a `first_is_search` binary column to the design matrix and refit. Does the posterior on its coefficient give a meaningful first-touch effect?
- Exercise 5: posterior shrinkage with multicollinear channels
  - Setup: Loop D's multicollinearity caveat says "when channels co-occur strongly in journeys, individual coefficient posteriors widen and may overlap zero".
  - Task: modify `simulate_journeys` so that whenever a journey contains `email` it also contains `direct` (with probability 1). Refit the additive Bayesian model. Inspect the marginal posteriors on `email` and `direct`.
  - Expected pattern: the marginals widen, possibly overlap zero, and the joint posterior on the pair is highly correlated. The model surfaces the identification problem honestly. The four heuristics give a single number per channel and silently split credit anyway.
  - Two-lens: the frequentist `statsmodels.GLM` fit shows the same problem as a near-singular design matrix and inflated standard errors on the two collinear coefficients. The chapter's "heuristic = accounting, Bayesian = causal under a likelihood" framing breaks down when the likelihood is unidentifiable, and both lenses agree it's broken.
  - Stretch: construct a dataset where `email` and `direct` are *anti-correlated* (one or the other but never both). Show that the marginals tighten dramatically.
- Exercise 6: two-lens shares head to head
  - Setup: re-run `render_bayesian_attribution`. The right panel of `images/bayesian_attribution.png` shows the four heuristic shares alongside the Bayesian-derived share (normalized non-negative coefficients).
  - Task: compute the L1 distance between (a) each heuristic's share vector and the true share vector, (b) the Bayesian share vector and the true share vector. Report all five distances.
  - Expected pattern: the Bayesian distance is smallest, by a margin that matters. Linear is the next-best heuristic. Last-touch is worst on this dataset because of `direct`'s closer effect.
  - Two-lens: this is the chapter's central two-lens comparison. There is no frequentist alternative to the Bayesian model that survives Loop C's recovery check, so the meaningful comparison is "deterministic accounting heuristics versus a likelihood-based posterior". Loop D's footnote on scales is essential reading: the comparison is between relative weights, not identically scaled probabilities.
  - Stretch: compute the same L1 distances using a 95% credible-interval lower bound for the Bayesian shares (worst-case Bayesian) instead of the posterior mean. Are the heuristics still worse?
- Exercise 7: a journey where every scheme agrees
  - Setup: construct a single hand-built dataset of 1,000 journeys where every journey has exactly 2 touches drawn uniformly from the 5 channels and the conversion probability is constant (no channel coefficients).
  - Task: run all four heuristics and the Bayesian additive model on this dataset. Compare shares and posterior coefficients.
  - Expected pattern: all four heuristics produce nearly identical shares (each channel near 1/5). The Bayesian posterior on every coefficient is concentrated near zero. The "no causal structure" case is the one case where the deterministic heuristics and the likelihood-based posterior return the same uninformative answer.
  - Stretch: on this dataset, what does Loop A's first-touch-vs-last-touch divergence look like? Why does the divergence shrink when channels are exchangeable?
- Carry-forward question: across 17 chapters of inference work, both lenses have been on the table from Chapter 1. Now that we have written down decision rules in code, would a frequentist team and a Bayesian team have actually shipped different products at the same company, on the same data, and where, and how often?
